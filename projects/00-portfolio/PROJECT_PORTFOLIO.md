# CogniSync Research & Product Portfolio

The supplied documents have been consolidated into five implementation tracks. The portfolio separates **source-derived knowledge**, **engineering hypotheses**, and **buildable product scope**.

| Project | Core idea | Primary technologies | Maturity |
|---|---|---|---|
| CogniSync Professional | Background agent + bounded autonomy | Strands, MCP, A2A, AgentCore path | Prototype |
| Sovereign Edge Agent | Local engineering intelligence under hardware constraints | Gemma 3, llama.cpp, MCP, SearXNG, Rclone, NSVIF | Architecture |
| Open Creator Layer | Buildbox-class UX over Unity/Unreal | Unity UI Toolkit, Graph/Blueprint systems, Smart Assets | MVP design |
| Influence Literacy Lab | Analyze and disclose persuasive mechanisms | NLP, visual rhetoric, UX audit, media literacy | Research product |
| AI Content Product Studio | Turn prompt knowledge into reusable digital products | LLMs, research, QA, packaging | Product design |

## Shared platform thesis

These projects can converge around one reusable infrastructure:

`Model Runtime → Tool Layer → Evidence/Memory → Policy → Verification → Human Gate → Artifact/Audit`

This creates a coherent portfolio instead of five unrelated experiments.

## Cross-project assets

- local model gateway;
- MCP connector catalog;
- A2A worker protocol;
- provenance/evidence schema;
- policy and human-approval layer;
- verification engine;
- benchmark harness;
- artifact packaging and audit trail.

## Strategic priority

1. **Ship CogniSync** as the reference implementation.
2. **Build Sovereign Edge Agent** as the local execution substrate.
3. **Use that substrate to accelerate Open Creator Layer**.
4. **Use the Influence Literacy Lab as a defensive evaluation capability** for persuasive interfaces and agent UX.
5. **Productize the Content Studio** once the shared research, memory, QA and publishing pipeline is mature.

## Boundary conditions

The source corpus contains claims, estimates, hypotheses and external references of varying confidence. Repository implementations therefore distinguish between:

- **documented source claim**;
- **engineering hypothesis to benchmark**;
- **verified implementation behavior**;
- **future roadmap item**.

This distinction is mandatory for technical credibility.
